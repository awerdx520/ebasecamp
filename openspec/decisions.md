# 架构决策日志

| 日期 | 决策 | 理由 | 详见 |
|---|---|---|---|
| 2026-10-22 | 采用「自有 Elisp 清单 + 生成 compose 执行」模型，而非直接扫描项目 compose 或自拼 docker 命令 | 需要表达「可复用基础组件 → 多项目绑定」的模板复用语义，纯 compose 与纯 CLI 都无法表达 | ADR-0001 |
| 2026-10-22 | 基础组件实例语义由组定义 `:scope shared / per-project` 声明，两种都支持 | 真实场景同时存在「全机共用一份 mysql」与「每项目独立 redis」 | ADR-0001 |
| 2026-10-22 | 清单用 Elisp 数据文件存于 `~/.config/ebasecamp/`，零外部依赖 | 用户已确认；避免引入 yaml.el，且 Elisp 可表达条件与覆盖逻辑 | ADR-0001 |
| 2026-10-22 | 与项目 compose 的同步为**单向**：导入（一次性迁移）+ 导出（部署用），不做双向回写 | 双向合并需保留注释/格式且冲突语义复杂，与确定性和零依赖目标冲突 | ADR-0001 |
| 2026-10-22 | 不引入 YAML 解析器：读取 YAML 一律走 `docker compose config --no-interpolate --no-env-resolution --no-path-resolution --format json` | 本机实测 Compose 5.6.0 支持，docker 即解析器，零依赖且语义权威；三个 flag 保证不泄漏变量值、env_file 内容与绝对路径 | ADR-0001 |
| 2026-10-22 | 统一 external network `ebasecamp`，shared 组以固定项目名 `ebc-shared` 运行 | 跨 compose 项目容器互通必须共享同一 network | ADR-0001 |
| 2026-10-22 | 导入项目 compose 必须使用 `docker compose config --no-interpolate --no-env-resolution --no-path-resolution --format json` | 实测：常规 `config` 会插值环境变量（`${SECRET}` → 明文或静默空串，退出码仍 0）、合并 env_file 内容、把相对路径绝对化；三个 flag 分别阻断这三类污染 | ADR-0001 |
| 2026-10-22 | `docs/` 下用户文档统一使用 `.org`；`openspec/` 下按工作流规则固定 `.md` | 用户以 org-mode 为主，避免同一目录格式混用 | ADR-0001 |
| 2026-10-23 | 组与项目的关联**改到组侧**（`ebasecamp-define-group :configs ((配置名 :project 项目 :services 覆盖))`），并在加载末尾由 `ebasecamp-model-link-configs` **物化**成既有 ref 形态并入 `project.groups`；`projects/*.el` 只写 `:title` / `:root` | ①组成为全局第一等对象——未关联任何项目的组在界面上依然可见，不再依赖别人的文件；②关联方向单一——「这个组给了哪些项目、各自覆盖什么」读 `:configs` 一处即可，覆盖集中可对齐；③物化产物与 `ebasecamp-model--group-ref-from-spec` 同构，compose / command / data / export 五个读取点零改动，风险面收敛在 model + config | ADR-0002 |
| 2026-10-23 | 否决「保持现状（项目侧 `:groups`）」 | 关联方向与「组 → 配置 → 项目」的产品目标相反，组可见性仍取决于是否被引用，从组视角读覆盖无法实现 | ADR-0002 |
| 2026-10-23 | 否决「引入虚拟项目承载无宿主的 shared 配置」 | 为让 `:project` 可省略而造隐式概念，会渗入 model / compose / command / data / ui 全部模块；改为 `:project` 必填 + 文案说明宿主仅作渲染与标签归属 | ADR-0002 |
| 2026-10-23 | 否决「配置独立成第三类清单 `configs.el`」 | 组 / 配置 / 项目三张表要互相对齐，加载顺序与引用完整性校验复杂度上升，而配置天然从属于组（配置名组内唯一、覆盖的是该组服务），无表达力收益 | ADR-0002 |
| 2026-10-23 | 否决「只改 UI 不改模型」 | 把项目侧 ref 当配置展示，界面有「配置」但用户写清单仍须从项目出发；展示层与清单层语义错位，等于把模型缺陷交给用户记忆承担 | ADR-0002 |
| 2026-10-23 | UI buffer 只读化（`ebasecamp-ui-mode` 派生 `special-mode` + `buffer-read-only t`，且 mode 必须在 `etaf-mount` **之前**启用）+ 键位单一来源 = etaf Host `:keys`（根级 9 条 / 段级 5 条，全部带 LABEL）+ 最外层 Host `:key-scope 'local` 吞未绑定 printing key + 唯一写入口 `e` → `groups.el` 定位；`SPC` 保持 ebox 的激活语义（等价 `RET`），行级勾选另绑 `t` | ①没身份的裸 buffer 会让 `i` 落到 evil 进 insert、能打字却写不到任何地方；②把键位绑在 major-mode map 无效（实测 `lookup-key` 命中但运行期 `key-binding` 为 `ignore`，被 etaf printing-key 层遮住），唯一可靠层是 Host `:keys`；③`[32]` 属 `ebox--activation-keys`（节点级 char-property keymap 先于 etaf 键层），`SPC` 不可重绑，`etaf-activate` 又按焦点宿主会误按按钮 → 改绑 `t`；④写能力应回到清单文件，界面保持只读投影 | 详见 ADR-0003 |
| 2026-10-23 | 否决「用 `evil-define-key` 硬依赖 evil 解决 insert 问题」 | 为「不该能打字」的 buffer 引入重度依赖，且只覆盖 evil 用户、不解决键位缺失与吞键；改为 `with-eval-after-load 'evil` + `evil-set-initial-state` 条件化，未装 evil 时零副作用 | ADR-0003 |
| 2026-10-23 | 界面根布局改为 **flex 三段式**（根 `flex :flex-direction 'column :height 'stretch`，顶栏 + 底栏各 `:flex-shrink 0`，中间区 `:flex-grow 1 :min-height '(lh 0)`），使总高 = 视口高、整窗不滚、底栏常驻；`column` / `row` 不走 flex 算法所以不能当根。否决「`:sticky top` 代替底栏」（只支持 top 且写 header-line 限单行）与「`:position 'absolute` 贴底」（相对内容盒，非视口） | etaf 无 fixed / sticky bottom，底栏排在内容之后必然被滚出视口；只有让根高恒等于视口高才能既钉住底栏又让左右两栏各自 `:overflow 'scroll'` 内部滚动 | ADR-0004 |
| 2026-10-23 | 配色改为 **主题两层**：基础色（前景 / 背景 / 面板 / 边框，9 个）从 Emacs face 取，状态色（26 个）走内置明暗两套 palette，按 `background-mode` 选择，合计 35 个 `:ui-*` token；`etaf-ref` 承载 + `etaf-theme-provide` 在 `:setup` 提供（render 期调用会 signal）+ `enable-theme-functions` / `disable-theme-functions` 钩子重算，`load-theme` 后属性级刷新。否决「只用硬编码明暗两套 plist 不读 face」（换主题后界面与编辑器割裂、基础色对比度会崩）与「引入主题库依赖」（破坏零外部依赖） | 硬编码色值在暗色主题下发白，且界面从未 provide token 导致 badge / alert 整体回退 etaf-ui 的单套浅色 palette | ADR-0004 |
| 2026-10-23 | 左栏宽度 **默认 0.26、可拖动、跨会话记住**：`etaf-splitter` 的 `:on-change` 收手势 plist、按指针 / 键盘两条分支折算比例，钳制 `[0.15, 0.55]`，持久化到 `<ebasecamp-cache-directory>/ui-state.el`（只存 `(:split-ratio FLOAT)`，`make-temp-file` + `rename-file` 原子覆盖，读前拒绝 `#.` 文本）。该文件是**运行时状态缓存**（不在清单目录、不参与 `ebasecamp-config-load`、不经 `e`、可随时删），不破坏 ADR-0003 的「清单唯一写入口」不变量 | 0.38 是为旧文案调的，右栏服务表格被挤；宽度是视图偏好，应记住但不应混入清单 | ADR-0004 |
| 2026-10-23 | 区域跳转用 `etaf-focus-within`（nil COUNT = 子树首个停靠点），三区域各加 `:ref`，根级键增 `1` / `2` / `3`（共 12 条），且键上绑的是三个**零参命令**而非带 interactive 参数的 `--focus-region`。否决「用 `TAB` 线性遍历代替」 | etaf 无「跳 group」API；`etaf--keys-run` 用 `call-interactively`，带 interactive 参数的函数直接绑键会先弹 `completing-read` 问区域；`TAB` 的语义是区域内移动，与跨区域跳转是两种操作 | ADR-0004 |
| 2026-10-23 | 打开界面时按 `default-directory` **自动定位**项目：最长 `:root` 前缀匹配（`file-truename` 双归一、`file-name-as-directory` 形态、大小写敏感），选中该项目「第一份配置」（组顺序 × `:configs` 顺序首个 `:project` 命中者）所在组；**无匹配则不选中任何组**，且只在建会话时算一次。否决「无匹配时回退到第一个组」（会删掉未选中态并让 4 项既有占位断言变红） | 从项目目录里进来却看不到该项目配置，等于每次都要手动找；而「不在任何项目里」本身就是有用信息，不该被静默掩盖 | ADR-0004 |
