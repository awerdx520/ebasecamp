# 技术债

| # | 条目 | 影响 | 处置计划 |
|---|---|---|---|
| 1 | 本机为 Compose **5.6.0**（新大版本），主版本语义与 v2.x 不同，`config --format json` 的键集可能变化 | 导入映射与生成物校验可能随版本漂移 | 已落地：T1.4 增加 `docker compose version` 检测与不匹配警告；JSON 结构差异收敛在 `ebasecamp-import.el` / `ebasecamp-docker.el` |
| 2 | etaf 0.2.3 / etaf-ui 0.1.3 处于快速演进期（Commentary 即公开 API 契约） | 升级可能破坏 UI | UI 逻辑集中在 `ebasecamp-ui.el` 单点；只用 Commentary 列出的公开符号 |
| 3 | 自写 YAML 序列化器只覆盖清单用到的字段 | 清单出现新字段时导出会丢字段 | 未识别字段存入 `:extra` 并原样回写；新增字段必须补 ERT 往返测试 |
| 4 | 容器状态采用 3s 轮询（仅 UI 可见时） | 状态延迟最多 3s，每次轮询起一个 docker 进程 | 轮询间隔做成 defcustom；后续评估 `docker events` 流 |

| 6 | `--no-interpolate` 输出的模型比常规 `config` 缺省更多字段（实测无 `command: null`、`entrypoint: null`、`ipam: {}`），且 `env_file` 条目形态随参数变化（无 `--no-interpolate` 时仅 `path`，有时含 `required: true`） | 导入解析若把「字段缺失 / 形态差异」当语义差异会误判 | 导入层按「字段可缺省、`env_file` 按路径列表归一」实现；ERT 用实测输出作 fixture |

| 9 | 自定义网络的 external 语义无法表达；跨组同名服务静默保留首个 | 用户无法引用已存在的外部网络；同名服务不会报错而是被静默丢弃 | M4 在 model 层加 `:external` 标记与服务名冲突校验 |
| 10 | Docker 无健康检查时 `HealthStatus` 为 `"none"` 而非空串 | status 层若原样透传，UI 会显示 `none` | T2.1 在状态归一化时把 `"none"` 与空串都归一为 nil |

| 12 | `make check-parens` 原先不覆盖 test/*.el，测试文件括号错漏时会静默吞掉用例 | 测试数下降但显示全绿 | 已在 T2.3 修复：`PARENS_FILES` 含 `TEST_FILES` |
| 13 | 按 scope 拆批执行后，per-project 生成物不含 shared 组服务，而 `depends_on` 可以跨 scope 引用共享服务名（如 per-project 的 `api` 写 `depends-on ("mysql")`，`mysql` 属 shared 组） | 该分支 `docker compose up` 会因「depends on undefined service」失败（T3.5 冒烟会暴露） | **已修复**（T3.1 补强）：①compose 层 `ebasecamp-compose-render` 在 `GROUP-FILTER` 非 nil（按 scope 渲染）时剔除指向本次未渲染服务的 `depends_on` 项（`ebasecamp-compose--filtered-depends-on`），无 filter 渲染（预览/导出）行为不变；②command 层 `ebasecamp-command-split-keys` 为 per-project 批次计算 `:requires-shared`（取自模型层**原始** `depends-on`），`ebasecamp-command-run` 在 `start` 时串行先跑覆盖这些依赖的 shared 批次、成功后才跑 per-project 批次，shared 失败即中止，并在 `on-complete` 暴露 `:auto-started-shared` 与 `:order`。遗留：剔除依赖时不单独告警（依赖改由 shared 批次补齐）；`stop` / `restart` / `down` 不做自动补齐 |
| 14 | `restart` 不补齐 shared 分支；`depends-on` 笔误（既非项目内也非 shared 服务）被静默剔除 | 重启后可能连不上已停的 shared 服务；清单笔误无提示 | M4 在 `split-keys` 增加未知依赖名校验，并让 restart 走与 start 相同的补齐逻辑 |
| 15 | `ebasecamp-ui` 的 `busy` 是会话级而非项目级 | 多项目并行被 UI 收窄为单飞 | 若允许多项目并行，把 busy 改为按项目哈希 |
| 16 | shared 容器无插件侧清理入口（`down` 只覆盖 per-project） | 删项目/卸载插件后 shared 容器残留，只能 `docker rm -f` | M4 增加 `ebasecamp-prune`（显式确认后清理 shared 与孤儿容器） |
| 17 | 导入成功后 UI 不自动切换到新项目 | 用户需手动点 tab | T4.4 遗留；M4 在导入成功后设置 current project |
