#+title: ebasecamp
#+author: Thomas
#+options: toc:nil

ebasecamp 是 Emacs 里的 Docker 环境分组管理插件。

* ebasecamp 是什么

ebasecamp 把 Docker 环境按「项目 → 组 → 服务」三层管理：服务组是可复用的基础组件集合（例如 mysql、redis），项目绑定若干组并可按项目覆盖端口、环境变量与卷。界面用 etaf / etaf-ui 在 Emacs buffer 内渲染，按服务多选即可批量启动、停止、重启。清单（组与项目定义）以 Elisp 形式保存在 =~/.config/ebasecamp/=，是唯一事实源；compose 文件只是由清单派生的生成物。插件还支持从已有 compose 文件导入清单，以及把项目导出为部署用 compose。

* 特性

- *组复用*：一个组定义可被多个项目引用；=:scope shared= 的组跨项目共用一套容器（compose 项目名固定 =ebc-shared=），=:scope per-project= 的组每个项目一套（=ebc-<project>=）。
- *服务级多选启停*：界面里勾选具体服务，批量执行启动 / 停止 / 重启，不强制整组起停。
- *状态轮询*：容器状态由 =docker ps --no-trunc= 采集并按标签归一，默认 3 秒轮询一次（见 =ebasecamp-status-refresh-interval=）。
- *导入已有 compose*：用 =docker compose config --no-interpolate= 系列 flag 读取项目 compose，映射为清单文件落盘。
- *导出部署用 compose*：把项目（含项目级覆盖）渲染为可直接部署的 compose 文件。
- *密钥只存引用*：清单里只保存 =${VAR}= 引用与相对路径，插件不读取、不打印、不落盘任何密钥值。

* 安装

** 依赖

| 依赖 | 版本要求 |
|------+----------|
| Emacs | ≥ 29.1 |
| etaf | 0.2.3 |
| etaf-ui | 0.1.3 |
| Docker + Compose | Compose 5.x（本插件按 Compose 5.6.0 实测） |

** 方式一：straight.el

#+begin_src elisp
(straight-use-package '(ebasecamp :local-repo "~/Workspace/ebasecamp"))
#+end_src

** 方式二：手工 load-path

#+begin_src elisp
(add-to-list 'load-path "~/Workspace/ebasecamp")
(add-to-list 'load-path "~/Workspace/ebasecamp/lisp")
(require 'ebasecamp)
#+end_src

=ebasecamp.el= 在仓库根目录，实现模块在 =lisp/= 下，两个路径都要加。

* 快速开始

1. 生成示例清单（=groups.el= 与 =projects/example.el=）：

   #+begin_src text
   M-x ebasecamp-create-sample-config
   #+end_src

   清单已存在时会报错拒绝覆盖；确实要覆盖时用 =C-u M-x ebasecamp-create-sample-config=。

2. 打开管理界面：

   #+begin_src text
   M-x ebasecamp
   #+end_src

界面分四区：

- *顶栏*：项目 tabs（切换项目）+ =刷新= 按钮；
- *组列表*：当前项目引用的组（左侧）；
- *服务表*：服务名 / 镜像 / 状态 / 端口 / 健康（右侧）；
- *操作条*：第一行 =启动选中= / =停止选中= / =重启选中= / =销毁环境=，第二行 =导入 compose= / =导出 compose=。

勾选流程：在服务表里勾选目标服务 → 点操作条按钮。勾选状态是项目级的，切换项目会清空勾选。=销毁环境= 会弹确认框，确认后只移除本项目（per-project）的容器，不删卷。

* 清单怎么写

清单目录默认为 =ebasecamp-config-directory=（=~/.config/ebasecamp/=）：

#+begin_src text
~/.config/ebasecamp/
├── groups.el        服务组定义（可选）
└── projects/*.el    项目定义，按文件名字典序加载
#+end_src

** groups.el 示例

#+begin_src elisp
;;; -*- lexical-binding: t; -*-

(ebasecamp-define-group postgres
  :title "PostgreSQL"
  :scope shared
  :services
  ((postgres :image "postgres:16"
             :ports ((5432 . 5432))
             :volumes ((:source "postgres-data"
                        :target "/var/lib/postgresql/data"
                        :type volume))
             :environment (("POSTGRES_PASSWORD"
                            . "${EBASECAMP_PG_PASSWORD}"))
             :healthcheck (:test ("CMD-SHELL" "pg_isready -U postgres")
                           :interval "10s")
             :restart "unless-stopped")))

(ebasecamp-define-group app
  :title "应用栈"
  :scope per-project
  :services
  ((api :image "example/api:latest"
        :ports ((8080 . 8000))
        :environment (("DATABASE_URL" . "${EBASECAMP_DATABASE_URL}"))
        :depends-on ("redis")
        :volumes ((:source "../api"
                   :target "/app"
                   :type bind
                   :read-only t)))
   (redis :image "redis:7")))
#+end_src

** projects/example.el 示例

#+begin_src elisp
;;; -*- lexical-binding: t; -*-

(ebasecamp-define-project example
  :title "示例项目"
  :root "~/Workspace/example"
  :shared-network t
  :export-file "deploy/compose.yaml"
  :groups ((postgres)
           (app
            :scope per-project
            :services
            ((api :ports ((18080 . 8000))
                  :environment (("LOG_LEVEL" . "debug")))))))
#+end_src

这段示例与上面的 =groups.el= 配套：=postgres= 组按组自身的 =shared= 进 =ebc-shared=，=app= 组在本项目内被覆盖为 per-project 并改掉了 =api= 的宿主端口与环境变量。

** 关键字表

组定义 =ebasecamp-define-group= 支持 =:title=、=:scope=、=:services=；=:scope= 取 =shared= 或 =per-project=，缺省 =per-project=。

项目定义 =ebasecamp-define-project= 支持 =:title=、=:root=、=:shared-network=、=:export-file=、=:groups=。=:shared-network= 缺省为 =t=，控制是否在生成物顶层把 =ebasecamp= 声明为 external network。

服务定义支持 =:image=（必填）、=:command=、=:entrypoint=、=:environment=、=:labels=、=:ports=、=:volumes=、=:healthcheck=、=:depends-on=、=:networks=、=:working-dir=、=:user=、=:restart=、=:extra=。

项目里的组引用支持 =:scope= 与 =:services= 两个关键字。未知关键字会报错（错误记入加载结果的 =:errors=，不中断其他文件）。

** 字段写法约定

- =:scope shared= 与 =:scope per-project= 的差异：shared 组渲染进 compose 项目 =ebc-shared=，跨项目共用同一套容器；per-project 组渲染进 =ebc-<project>=，每个项目各自一套。两组分别落在不同 compose 项目里，网络通过 external network =ebasecamp= 互通。
- =ports= 用 =("PUBLISHED . TARGET)= 整数对，例如 =(3306 . 3306)= 表示宿主 3306 → 容器 3306。
- =volumes= 用 plist：=(:source S :target T :type volume|bind [:read-only t])=。=:read-only= 非 nil 时挂载追加 =:ro=。
- =environment= 与 =labels= 是字符串 alist，值用 =${VAR}= 引用，插件原样保留不插值。
- =:extra= 存放清单未识别的 compose 字段，导出时原样回写；清单层不校验其键名。

** 项目覆盖

项目对组的覆盖有两个层面：

- *=:scope= 覆盖*：项目里写 =(:group ... :scope shared)= 只改变该项目的解析语义，不修改组对象本身。
- *=:services= 字段覆盖*：按服务名覆盖字段。=environment=、=labels=、=:extra= 按键合并（项目值覆盖同键、其余键保留），=image=、=command=、=entrypoint=、=ports=、=volumes=、=healthcheck=、=depends-on=、=networks=、=working-dir=、=user=、=restart= 整体替换。

覆盖不存在的服务名会报错。

* 安全约束

- 清单只保存 =${VAR}= 引用与相对路径，不落盘密钥明文；
- 读取项目 compose 只用 =docker compose config --no-interpolate --no-env-resolution --no-path-resolution --format json=，三个 flag 缺一不可：分别避免密钥明文展开、=env_file= 内容被合并、相对路径被绝对化；
- 生成物（=~/.cache/ebasecamp/<project>/compose.yaml=）中同样只有 =${VAR}= 引用，不含明文；
- 校验用 =config -q=，并且同时检查退出码与 stderr（退出码 0 不足以判定通过）。

* 已知限制

- 按 Compose 5.x 实测（本机 5.6.0），其他主版本的 =--format json= 键集可能不同；插件有 =docker compose version= 检测，不匹配时会告警。
- shared 组没有插件侧清理入口：=销毁环境= 只覆盖 per-project，shared 容器需 =docker rm -f=，M4 计划提供 prune。
- 容器状态是 3 秒轮询（仅界面可见时），状态最多滞后一个轮询周期。
- 自定义网络的 external 语义无法表达；跨组同名服务静默保留首个，不报错。
- =:extra= 字段原样透传，清单层不做 schema 校验，写错字段会导致 =config -q= 失败。
- 不做清单与项目 compose 的双向同步；导入是单向的，导出也是单向的。
- =重启选中= 不补齐 shared 依赖分支（=启动选中= 才会自动先起 shared 批次）；=depends-on= 里的笔误也会被静默剔除。

* 开发

所有验证走 =emacs -Q --batch=，不加载用户 init：

| 命令 | 作用 |
|------+------|
| =make check= | 串联执行下面三个子目标，任一失败即非零退出（提交前必跑）。 |
| =make check-parens= | 对 =*.el=、=lisp/*.el= 与 =test/*.el= 逐个做括号平衡检查。 |
| =make compile= | 字节编译，启用 =byte-compile-error-on-warn=，零 warning 才算通过。 |
| =make test= | 用 ERT 运行 =test/*-tests.el=。 |
| =make clean= | 删除与 =.el= 同名的 =.elc=。 |

=ELPA_LOAD_PATH= 指向 straight 的 build 目录，使 batch 模式下能 =require= etaf 系列包（=etaf=、=etaf-ui=、=ebox=、=ecss=）。换 Emacs 版本或路径时用变量覆盖：

#+begin_src text
make check EMACS=/path/to/emacs STRAIGHT_BUILD=/path/to/build-XX.X
#+end_src

修改 =Makefile= 后至少跑一次 =make check=。
