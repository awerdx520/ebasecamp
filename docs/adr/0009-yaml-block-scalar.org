#+title: ADR-0009 多行字符串的 YAML 标量渲染（块标量 + 换行转义）
#+date: 2026-10-26
#+status: 已接受（Accepted）

* 背景

自写 YAML 序列化器原先只有两种标量形态： *裸标量* （ =key: value= ）与 *双引号单行标量* （ =key: "value"= ）。这与「清单里的值都是单行」的假设配套 —— 直到 compose 顶层 =configs= / =secrets= 引入 inline =content:= ，该假设当场失效。

两处判定同时漏掉了换行：

- =ebasecamp-compose--escape-string= 只转义反斜杠与双引号。真实换行被原样带进双引号标量内部，而 YAML 的 flow scalar 会把换行 *折叠成空格* —— 转义函数「成功执行」但语义已丢。
- =ebasecamp-compose--quote-required-p= 的判据（空串 / 前后空白 / YAML 特殊字符 / 形如数字 / 形如布尔）不含换行，因此多行字符串在某些上下文里会落到 *裸标量* ，更糟。

后果是 *静默改内容* ：顶层 =configs= / =secrets= 的 inline 多行 =content:= 经「导入 → 渲染」后被折叠。实测（本机 =datarush-go= 原 compose）中 =prometheus_config= 由 896B / 35 行变成 762B / 4 行，=grafana_clickhouse_datasource= 由 340B / 14 行变成 282B / 0 行。

关键在于 *校验完全无感* ： =docker compose config -q= 对这两份生成物仍 exit 0、stderr 空 —— 它只校验语法与 schema，不校验 =content= 的内容是否等于原文。于是缺陷一路穿到容器启动，直到某个服务读到被压成一行的 nginx.conf / 私钥片段才暴露。这是与 ADR-0007 决策 2 同一族的静默通路： *校验通过 ≠ 内容正确* 。

* 决策

三层策略： *块标量* （block 上下文可读） / *双引号转义* （非 block 上下文保真） / *裸标量* （单行，逐字节不变）。

** 1. 保真层（A1）：转义换行与回车

- =ebasecamp-compose--escape-string= 转义四类字符：反斜杠、双引号、换行 =\\n= 、回车 =\\r= 。
- *换行与回车必须转成「字面两字符」* （反斜杠 + 字母 n / 反斜杠 + 字母 r）。复用 =(concat "\\" match)= 会产出「反斜杠 + 真实换行」，在 YAML 双引号标量里 *仍是换行* ，等于没修。这是本决策最容易写错的一处。
- 实现用 *一次* =replace-regexp-in-string= 配 =cond= 分派：换行 → 两字符字面量、回车 → 两字符字面量、其余 → 补反斜杠。 *不要* 写成多轮替换 —— 第二轮会把第一轮插入的反斜杠再转义一遍。
- =ebasecamp-compose--quote-required-p= 新增判定： *字符串含换行或回车即必须加引号* 。回车必须与换行 *一并* 加：含 CRLF 的字符串因含回车而不走块标量（见决策 2），若它同时不被判「必须加引号」，就会落到裸标量，内容直接损坏。
- 该改动自动覆盖 flow 序列（其条目同样经 =--escape-string= ），因此 =command: ["sh", "-c", "line1\nline2"]= 这类形态也保真。

** 2. 可读层（A2）：block 上下文渲染为块标量

=--yaml-value= 的映射分支与序列分支（block 上下文）在标量分支之前新增一条判定： *含换行且不含回车* 的字符串渲染为块标量。

- *含回车的字符串故意不走块标量* ：CRLF 若走块标量就必须把 =\\r\\n= 改写成 =\\n= ，那是 *静默改内容* ，与本节目的相反；因此让它退回双引号 + 转义保真。
- *chomping 按末尾换行数 n 选择* ：n 为 0 → =|-= （strip）、n 为 1 → =|= （clip）、n 大于等于 2 → =|+= （keep）。
- *内容行缩进为键缩进 + 2* ，由 =indent= 参数推导， *不硬编码具体列数* 。顶层段落形如 =configs:= （0 缩进） → 键 2 → =content: |= 4 → 内容行 6，全部由这一条规则推出。
- *空行输出空串* （不加缩进）：加了会产生尾随空格，往返后字节数变多。
- =|+= 的 n 个尾换行由 =(make-string n ?\n)= 拼在内容行之后（内容行本身末尾不带换行）。

** 3. 拼接触点：同层条目拼接改为 =--yaml-join=

块标量的返回值 *自带* n 个尾换行（ =|= 为 1、=|+= 为 n ）。原先同层条目用 =(mapconcat … "\n")= 无条件补分隔符，于是块标量之后还有同层键时 *多出 1 个换行* ：

- =|+= （keep）会把这个多出的空行计入内容 —— 实测 =content: |+= 写 =x\ny\n\n= ，回读成 =x\ny\n\n\n= ，即 *保真又破了* ；
- =|= （clip）与 =|-= 此前「看起来没问题」，靠的是 clip 恰好吞掉尾部空行 —— 属 *偶然* 而非正确，换个上下文就会翻车。

因此新增内部助手 =--yaml-join= ：按「已累积结果是否以换行结尾」决定是否补分隔符，替换 =--yaml-value= 映射 / 序列两个分支的 =mapconcat= 。判据取 *累积结果* 而非「只看前一项」—— 空串项、连续块标量才自洽。块标量函数本身不动（其 n 个换行语义正确），其它不走块标量的 =mapconcat= 调用点（如 =--service-body= ）不动。

* 影响面

| 路径 | 覆盖字段 | 保真手段 |
|---|---|---|
| =--yaml-value= （映射 / 序列分支） | 顶层 =configs= / =secrets= 的 =content= 、服务级 =environment= / =labels= 的值 | 块标量（A2），含回车时退回双引号转义 |
| =--service-body= （ =command= 等） | =command= / =entrypoint= / =healthcheck= 里的字符串 | 双引号转义（A1）， *不加块标量分支* |
| =--yaml-flow-sequence= | flow 序列条目（如 =command: ["sh", "-c", "…"]= ） | 双引号转义（A1） |

- =command= 等字段 *不要* 加块标量：它们的行内形态（ =sh -c "…"= ）与块标量的多行语义不同，加进去会把单行命令拆成多行 shell 参数，属于改变语义。

* 边界

| 情形 | 处理 |
|---|---|
| 字符串无换行 | 走既有标量路径，输出 *逐字节不变* （单行零变化是硬要求，避免生成物 diff 噪音） |
| 字符串含回车（CRLF） | 不走块标量 → 强制加引号 → 双引号 + =\\r= / =\\n= 转义保真（不改写内容） |
| 空字符串 | 维持 =""= |
| 字符串以换行开头（首行为空） | 块标量首行为空行（无缩进） |
| 内容行含前导空格 | 保留（缩进前缀 + 原行） |
| 内容行含 tab | 保留，不转义 |
| 内容行是纯空白（如两个空格） | 输出缩进 + 原空白（属内容，不折叠） |
| 只含一个换行（ ="\n"= ） | n 为 1 → clip 头，内容为 1 个空行 |
| 非字符串值（列表 / 映射） | 不进入块标量分支，行为不变 |

* 否决项

** ① 导入时对含多行 =content:= 的顶层 config 拒绝建模 + warning

「宁可不导入也不要静默改内容」在原则上正确，但后果是 *既有清单无法导入* ：现网 =datarush-go= 的三个顶层 config 全是 inline =content:= ，拒绝建模等于让用户 *手工改写原 compose* 才能用本插件。把「插件缺陷」转嫁成「用户改配置」，且没有过渡期。实现层修正（本 ADR）能在不动任何用户文件的前提下达到同等保真，故否决。

** ② 引入通用 YAML 库

违反仓库「零外部依赖（除 etaf / etaf-ui）」的约束（AGENTS.md 项目概述）。为一段 =content:= 引入一个 YAML 实现（及其缩进 / chomping / 编码语义）与为几个字段写 30 行序列化，风险收益完全不对等：库的行为变更会反过来成为插件的兼容负担，而插件只需要「清单用到的子集」逐字节可预期。

** ③ 把 =\r\n= 统一改写成 =\n=

看起来「反正 compose 里 CRLF 无意义」，但这是 *静默改内容* 的同一类问题 —— 用户 =content:= 里的字节被换了，若下游是二进制敏感的配置（校验和、脚本）就会出问题。本 ADR 一律 *保真* ：CRLF 保留为转义后的 =\\r\\n= ，是否规整由用户决定。

* 与 ADR-0006 的关系

ADR-0006 决策 3 记录顶层 =configs= / =secrets= 的模型与渲染口径，并明确「第一版只保证 =file:= / =external= / =name:= 形态往返」—— 即 inline =content:= 的多行形态当时 *已知未覆盖* 。本 ADR 补齐该形态：模型层不变（仍是「字符串键的 alist」），只在 *渲染层* 增加块标量分支与换行转义。技术债 #33 由此关闭。

* 验证证据

*L3 真实 docker 往返* （ =datarush-go= 原 compose → 导入 → 渲染 → 两侧同款读回命令 =config --no-interpolate --no-env-resolution --no-path-resolution --format json= ，逐键 =equal= 比较）：

| 键 | 结果 | 字节（原 / 渲染） | 换行数（原 / 渲染） |
|---|---|---|---|
| =grafana_clickhouse_datasource= | *全等* | 340 / 340 | 14 / 14 |
| =grafana_prometheus_datasource= | *全等* | 159 / 159 | 8 / 8 |
| =prometheus_config= | *全等* | 896 / 896 | 35 / 35 |

生成物 =docker compose config -q= exit 0、stdout 与 stderr 均 0 字节。

- *|+ 拼接缺陷最小复现* ：同一份 =content: |+= （原文 =x\ny\n\n= ）经导入 → 渲染 → 往返，修复前 =equal= 为 *False* （回读 =x\ny\n\n\n= ），修复后 *True* 。

*判据纪律* ： =config -q= *不能* 作为保真判据（它只校验语法与 schema）。必须用 =--format json= 取回 =content= 字符串做等值比较，且读回命令必须带齐三个 =--no-*= flag（不变量 5），否则插值 / 环境合并 / 路径绝对化都会污染比较对象。

* 不变量

*无新增不变量* 。本 ADR 属 *实现层修正* —— 不变量 6（清单只保存引用、不落盘密钥值）与不变量 3（网络）等均不受影响；单行标量输出逐字节不变由既有 452 项测试守。判据纪律（ =config -q= 不足以判保真）沿用 ADR-0006 / ADR-0007 已记录的教训，不上升为新的机械检查项。
