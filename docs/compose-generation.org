#+title: ebasecamp compose 生成与导入导出
#+author: Thomas
#+options: toc:t

本文描述 *当前实现* （HEAD，v0.2 批次 C6 完成态）的 compose 读写规则。代码是最终依据：文档与 =lisp/= 冲突时以代码为准，并回头修文档。

相关实现：=lisp/ebasecamp-compose.el= （清单 → YAML 渲染）、=lisp/ebasecamp-import.el= （compose JSON → 清单 + 落盘）、=lisp/ebasecamp-export.el= （部署物导出）、=lisp/ebasecamp-docker.el= （docker 调用与 =config -q= 校验）。

* 方向：清单是事实源，compose 是派生物

compose 文件在本插件里只有一个合法来源方向： *清单 → compose*。反向的 compose → 清单只发生在用户显式触发的导入，且导入结果立即落成 Elisp 清单（之后 compose 文件不再被引用）。

| 链路 | 产物 | 路径 | 何时产生 | 用途 |
|------+------+------+----------+------|
| 缓存生成物 | =compose.yaml= | =<ebasecamp-cache-directory>/<project>/compose.yaml=（默认 =~/.cache/ebasecamp/=；全部 shared 时为 =_shared/compose.yaml=） | =ebasecamp-compose-write= 按 scope 渲染后写盘 | =docker compose -f <该文件> up/stop= 的实际执行输入；可随时重建， *不得手工编辑* |
| 部署导出物 | =docker-compose.ebasecamp.yaml= | =<project :root>= 下，或项目 =:export-file= 指定处 | 用户显式 =M-x ebasecamp-export-compose= | 交给部署环境（脱离 ebasecamp）直接 =docker compose up -d= |

两条链路的差别是 *输入调整* 而不是两套渲染代码：导出复用 =ebasecamp-compose-render= ，只在渲染前做两件事（只渲 per-project 组、关闭 =:shared-network=）。因此 YAML 语法、标签注入、卷命名、=depends_on= 处理两边完全一致。

* 读取项目 compose：唯一合法命令

#+begin_src text
docker compose -f <file> config --no-interpolate --no-env-resolution --no-path-resolution --format json
#+end_src

三个 =--no-*= flag 与 =--format json= 固定在 =ebasecamp-import--config-arguments= 里，由 =ebasecamp-import-parse= 与 =ebasecamp-import--config-json= 两处唯一使用（AGENTS.md 不变量 5）。 *缺任一 flag 即违反不变量* ，后果各不相同：

| flag | 缺了会怎样 |
|------+------------|
| =--no-interpolate= | =${VAR}= 被展开成 *明文密钥* 或被静默置空（变量未设时 =exit 0=、无告警），导入把明文写进清单 —— 直接违反「清单只保存引用」 |
| =--no-env-resolution= | =env_file= 指向的文件内容被 *合并进* 输出，清单里出现来自密钥文件的键值；同时 =env_file= 条目形态漂移 |
| =--no-path-resolution= | bind 卷与 =env_file= 的相对路径被 *绝对化* 成 =/home/<user>/…=，清单失去可迁移性 |
| =--format json= | 输出是 YAML，导入层只能 JSON 解析，直接报「compose 配置不是合法 JSON」 |

其他要点：

- =--no-interpolate= 的输出比常规 =config= *字段更少* （实测无 =command: null= 、=entrypoint: null= 、=ipam: {}=），导入层按「字段可缺省」处理，不把缺失当语义差异。
- 命令里 *不传* =-p=：compose 项目名只影响 =docker compose= 的容器/网络前缀，导入不需要；顶层 =name= 仅用于推断建议项目名。
- 退出码非 0 时 =ebasecamp-import-parse= signal =ebasecamp-import-error=，消息携带 stderr 首行（便于看清是 compose 语法错、文件不存在还是 =env_file= 缺失）。

* 导入映射（compose JSON → 清单）

** 解析管线

1. =json-parse-string= 用 =:object-type 'hash-table= 、=:array-type 'list= 、=:null-object nil= 解析 —— hash-table 的键天然是字符串，避免 alist 模式下 =image= / =working_dir= 这类合法标识符键被转成 symbol；hash-table 与数组类型上无歧义。
2. =ebasecamp-import--json->sexp= 把 hash-table 递归转成 *字符串键 alist* ，对象键按 =string<= 排序，数组保持原序。因此导入产物的服务顺序与字段顺序都是 *字母序* ，不是 compose 文件里的书写顺序。
3. JSON =null= → nil，=false= → 符号 =:false= （与 =true= 的 =t= 区分），数字原样。

** 逐字段映射表

| compose JSON（=services.<name>= 下） | 清单字段 | 规则 |
|--------------------------------------+----------+------|
| =image= | =:image= | 原样取字符串；缺失或空串 → 模型层报「缺少必填的 =:image= 字符串」，整次导入失败 |
| =command= | =:command= | 数组 → 字符串列表；字符串（shell 形式）→ 原样字符串（保留 shell 语义）；=null= → nil |
| =entrypoint= | =:entrypoint= | 同 =command= |
| =environment= | =:environment= | map → 字符串点对 alist；数组 =KEY=VALUE= → 按 *第一个* = 切分（无 = 时值为空串）；=null= 值 → 空串；数字 → 十进制文本；=false= → ="false"= |
| =labels= | =:labels= | 同 environment 的归一，然后 *剔除* 前缀 =ebasecamp.= 与 =com.docker.compose.= 的键 |
| =ports= （可表达） | =:ports= | =(PUBLISHED . TARGET)= 整数对 |
| =ports= （不可表达） | =:extra= 的 ="ports"= 桶 | 保留 *原始端口对象* （alist），不丢字段 |
| =volumes= （=type= 为 =bind= 或 =volume= ） | =:volumes= | plist =(:source S :target T :type bind= 或 =volume [:read-only t])= |
| =volumes= （其他，如 tmpfs） | =:extra= 的 ="volumes"= 桶 | 保留原始对象 |
| =networks= | =:networks= | map 取键名、数组取元素；剔除 =default= |
| =depends_on= | =:depends-on= | 对象形态（带 =condition=）取键名、数组形态取元素；两形态都归一为服务名列表 |
| =healthcheck= | =:healthcheck= | 只取 =test= / =interval= / =timeout= / =retries= / =start_period= 五项，转扁平 plist（=:start-period=）；缺失或空对象 → nil |
| =working_dir= | =:working-dir= | 原样 |
| =user= | =:user= | 原样 |
| =restart= | =:restart= | 原样 |
| =env_file= | =:extra= 的 ="env_file"= 桶 | *相对路径字符串列表* （见下） |
| 其余未识别字段 | =:extra= | 原样保留（键为字符串）供导出回写 |
| 顶层 =name= | 不写入清单 | 仅用于推断建议项目名 |

** ports：可表达 / 不可表达的分界

一个端口对象只有 *同时* 满足四条才进 =:ports= ：

1. 有整数 =target= ；
2. 有可解析的 =published= （整数、="8080"= 、或含 IP 的 ="127.0.0.1:9090"= —— 取最后一个 =:= 之后的端口段转整数）；
3. =protocol= 缺省或等于 ="tcp"= ；
4. =host_ip= 缺省，或取值属「绑定全部接口」集合：=0.0.0.0= 、=::= 、=[::]= 、空串。

任一不满足 → 整个端口对象进 =:extra= 的 ="ports"= 桶（含 =mode= / =protocol= / =published= / =target= 等全部原始字段）。清单没有表达 udp、端口区间、特定宿主 IP 的字段，透传是唯一不丢信息的选择。

** labels：剔除两个前缀

- =ebasecamp.*= ：插件自己注入的托管标签（导入时不回写，导出时重新注入，避免重复与伪造）；
- =com.docker.compose.*= ：compose 运行时生成的标签（配置哈希、项目名、服务名等），不属于用户的语义。

其余标签（如 =com.example.team= ）原样保留，导出时排在注入标签之前。

** env_file：字符串列表（D4）

compose 的 =env_file= 合法形态是「字符串 / 字符串列表 / ={path, required, format}= 对象」。导入统一归一为 *相对路径字符串列表* ：

- 字符串 → =("./db.env")= ；
- 对象 → 只取 =path= ，无 =path= 的项丢弃（顺序不变）；
- 路径保持相对（依赖 =--no-path-resolution=）， *不读取文件内容* 。

不能存成 volumes 语义的 =(:source PATH :type env)= 列表：=env_file= 只接受字符串或字符串列表，且「元素为 plist 的列表」会被渲染层的映射判据误判，导出产出 compose 无法解析的 YAML（D3 实测缺陷，D4 修复）。

** :extra 的组装顺序

=:extra= 由四段拼成，顺序固定：① 未识别字段（字母序）；② ="ports"= 桶；③ ="volumes"= 桶；④ ="env_file"= 桶（为空时省略）。导出时 =:extra= 原样展开到服务体末尾。

** 建议项目名

=ebasecamp-import-suggest-name= 的优先级：JSON 顶层 =name= （合法则小写采用）→ 文件父目录名 → 文件名（去扩展名）→ =imported= 。合法形式为 =[a-z0-9_-]+= ；=M-x ebasecamp-import-file= 会把它作为迷你缓冲区默认值，用户可改。

* 落盘格式（v0.2「组内配置」）

=ebasecamp-import-apply= 只写一个文件：=<ebasecamp-config-directory>/projects/<name>.el=，内含 *两个顶层 form* —— 一份 =ebasecamp-define-group= （服务定义 + 组内 =:configs= ）与一份 =ebasecamp-define-project= 。组名 = 项目名：模型没有「项目内联服务」，服务必须挂在组上，同名既保证项目内组引用唯一，也让不同项目的同名服务在注册表里互不冲突。

文件名与项目名一致，=--force= 为 nil 且文件已存在时 signal（不动原文件）。

** 示例

下面这段是 *当前代码的真实输出* （D3 实测 compose 输出 =test/fixtures/compose-config-noint.json= 经 =ebasecamp-import--manifest-content= 渲染，未手工改动）：

#+begin_src elisp
;;; -*- lexical-binding: t; -*-
;;; demo.el --- ebasecamp 清单（由 compose 导入）

;; 由 M-x ebasecamp-import-file 从 /home/thomas/work/demo/compose.yaml 导入。
;; 安全约定：只保存 ${VAR} 引用，不保存密钥明文。

(ebasecamp-define-group demo
  :title "demo"
  :scope per-project
  :services
  ((api
    :image "myapp/api:dev"
    :command ("sh" "-c" "run --port 8080")
    :entrypoint ("/entry.sh")
    :environment (("CACHE_URL" . "redis://cache:6379/0") ("DB_HOST" . "mysql") ("SECRET_DEFAULT" . "${PROBE_OTHER:-fallback}") ("SECRET_REF" . "${PROBE_SECRET}"))
    :labels (("com.example.team" . "backend"))
    :ports ((8080 . 80))
    :volumes ((:source "./src" :target "/app/src" :type bind :read-only t) (:source "api-cache" :target "/cache" :type volume))
    :depends-on ("cache")
    :networks ("backend")
    :healthcheck (:test ("CMD" "curl" "-f" "http://localhost/health") :interval "10s" :retries 3)
    :working-dir "/app"
    :user "1000:1000"
    :restart "unless-stopped"
    :extra (("shm_size" . "128m") ("ports" (("host_ip" . "127.0.0.1") ("mode" . "ingress") ("protocol" . "udp") ("published" . "9090") ("target" . 9090))) ("env_file" "./api.env")))
   (cache
    :image "redis:7.4"
    :networks ("backend")))
  :configs ((demo :project demo)))

(ebasecamp-define-project demo
  :title "demo"
  :root "/home/thomas/work/demo")
#+end_src

** 格式规则

| 项 | 规则 |
|----+------|
| 文件头 | 首行 =;;; -*- lexical-binding: t; -*-= ，次行 =;;; <name>.el --- ebasecamp 清单（由 compose 导入）= ，空行后两行注释交代来源与安全约定 |
| 服务体 | 每个服务形如 =(NAME :KEY VALUE …)=，首行不缩进、续行 4 空格 |
| 字段顺序 | =:image= → =:command= → =:entrypoint= → =:environment= → =:labels= → =:ports= → =:volumes= → =:depends-on= → =:networks= → =:healthcheck= → =:working-dir= → =:user= → =:restart= → =:extra= （固定顺序，便于 diff） |
| 省略规则 | 值为 nil 的键与空的 =:extra= 一律不写；服务无任何字段时写成 =(NAME)= |
| 组内配置 | =:configs ((<name> :project <name>))= —— 配置名取项目名，覆盖留空（服务定义已在组侧） |
| 项目定义 | 只写 =:title= 与 =:root= ， *不写* =:groups= （项目侧组引用由加载期物化产生，两处都写会构成「同项目同组双引用」而被加载层报错） |
| 字面量 | =prin1-to-string= 且关掉 =print-length= / =print-level= 、=print-escape-newlines= 为 t；因此 =${VAR}= 与相对路径 *原样保留* ，多行字符串不破坏版式 |
| 换行 | 文件以单个换行结尾 |

** 写盘后的自校验（失败即回滚）

1. 读回全部顶层 form，必须可解析且数量恰为 2（=ebasecamp-import--manifest-form-count=）。临时 buffer 里 =read= 不认 =;= 注释，读之前用 =forward-comment= 显式跳过。
2. 跑一次 =ebasecamp-config-load= 并断言三件事：零错误、新项目已注册、组内 =:configs= 已物化出 *带 =:service-overrides= 键* 的组引用（=plist-member= 判存在，不用取值判空 —— 无覆盖时该键存在且值为 nil）。

任一步失败：原来有文件则恢复原内容，否则删除新文件，然后 signal =ebasecamp-import-error= 。清单里只有 =${VAR}= 引用与相对路径，导入过程不读取、不打印、不落盘任何密钥值。

* 导出规则

| 项 | 规则 |
|----+------|
| 入口 | =ebasecamp-export-project PROJECT &key file force=（可编程）/ =M-x ebasecamp-export-compose=（交互，先用 =completing-read= 选项目） |
| 渲染范围 | *只渲染 per-project 组* （按 =ebasecamp-compose--ref-scope= 判定，引用上的 =:scope= 覆盖组声明）；shared 组服务由部署环境自行提供 |
| 网络 | 用 =copy-ebasecamp-project= 的 *副本* 渲染并把 =:shared-network= 置 nil → 导出物不声明 =ebasecamp= external network；服务的自定义网络照旧声明，由 compose 按项目自建 =<compose 项目名>_<网络名>= |
| 默认路径 | =<project :root>/docker-compose.ebasecamp.yaml= ；项目 =:export-file= 优先，相对路径按 =:root= 展开 |
| 路径无法推导 | 既无 =:root= 又无 =:export-file= → signal（派生物必须定位到项目仓库） |
| 无 per-project 组 | signal「没有 per-project 组，无可导出的服务」（不产出空部署文件，避免静默产出被误用） |
| 落盘 | 原子写：写同目录 =<target>.tmp= → =ebasecamp-docker-check-compose= 校验 → 通过则 =rename-file= 到目标（=ok= 为 nil 时删 tmp、signal，目标路径 *不会出现半写文件* ） |
| 编码 | =coding-system-for-write= 绑 =utf-8-unix= |
| 冲突 | =:force= 非 nil → 直接覆盖；非交互（=noninteractive= 或非交互调用）→ signal「已存在；覆盖需显式指定 :force」；交互 → 三选一 =[r] 换一个路径 / [o] 覆盖 / [c] 取消= （=r= 递归让用户 =read-file-name= 重新指定） |

** 头注释

导出物以四段式注释块开头（全部以 =#= 起始，不影响 =docker compose config= ）：

#+begin_src text
# 由 ebasecamp 生成，请勿手工编辑。
#
# 项目：demo
# 事实源：/home/thomas/.config/ebasecamp/projects/demo.el
# 重新生成：M-x ebasecamp-export-compose 选择项目 demo，或
#   (ebasecamp-export-project (ebasecamp-model-project 'demo) :force t)
#
# 说明：只含项目 demo 的 per-project 组服务（组：app、web）。
#       shared 组（mysql）的服务由部署环境自行提供，不在本文件中。
#       因此本文件不声明 ebasecamp 共享网络；服务原有的自定义网络由
#       compose 按项目自建（demo_<网络名>）。
#+end_src

四段职责：① 来源与「勿手工编辑」；② 事实源清单路径；③ 重新生成的两条途径（交互命令 / 可编程调用）；④ 渲染范围与网络语义（未引用 shared 组时第 5 行改为「本项目未引用 shared 组。」）。

* YAML 渲染规则

** 输出结构

段顺序固定：=name:= → =services:= → =networks:= （=:shared-network= 非 nil 或有自定义网络时）→ =volumes:= （有命名卷时）。段落之间单换行，文本以单个换行结尾；服务为空时输出 =services: {}= 。

单个服务体的字段顺序固定：=image= → =entrypoint= / =command= → =working_dir= / =user= / =restart= → =environment= → =labels= → =ports= → =volumes= → =networks= → =depends_on= → =healthcheck= → =:extra= 展开。2 空格缩进、block style。

** 映射 vs 序列的判定（D5 收紧后）

渲染器没有 YAML 类型信息，只有一个判据 =ebasecamp-compose--mapping-p= ：

#+begin_src elisp
(and (consp value) (consp (car value)) (stringp (caar value)))
#+end_src

即「非空列表 + 首元素是 cons + 首元素 car 是字符串」才当 *映射* 展开成 =key: value= 行。三条后果：

1. =environment= / =labels= / =:extra= 的普通项是 *字符串键点对* → 映射；
2. =:extra= 里的 *对象列表* （端口对象、volumes 对象这类「list-of-alists」）首元素 car 是 cons、不是字符串 → 走 *序列* 分支，渲染为 compose 长语法：

#+begin_src yaml
    ports:
      -
        host_ip: 127.0.0.1
        mode: ingress
        protocol: udp
        published: "9090"
        target: 9090
#+end_src

3. 若判据放宽到只看 =(consp (car value))= ，上述载荷会被当映射展开，产出 =(host_ip . 127.0.0.1):= 这类垃圾键、=config -q= 报 =services.<x>.ports must be a array= （tech-debt #21，D5 已修）。因此 *清单里 alist 的键必须全是字符串* ；塞 keyword plist 进 =:extra= 会让判据失效。

*已知副作用* ：=:extra= 的 ="ports"= / ="volumes"= 桶与 =:ports= / =:volumes= 字段 *同时非空* 时，服务体里会出现两个同名键，YAML 解析器直接拒绝（实测 =mapping key "ports" already defined= ，退出码 1）。见「已知限制」。

** flow 序列 vs block 序列

| 场景 | 形态 | 例子 |
|------+------+------|
| =command= / =entrypoint= 为列表 | flow（元素一律加双引号） | =command: ["sh","-c","run --port 8080"]= |
| =healthcheck= 的列表值（=test=） | flow | =test: ["CMD","curl","-f","http://localhost/health"]= |
| =ports= / =volumes= / =networks= / =depends_on= / =:extra= 的列表 | block，每项 =  - item= | =- "8080:80"= |
| 元素本身是列表 | block 长语法 =-= 换行后缩进 2 空格展开 | 见上文端口对象 |

** 标量引号规则

需要双引号的条件（任一命中）：空串、前后有空白、含 YAML 特殊字符 =:#{}[],&*!|>'\"%@`= 、形如整数/小数、形如布尔或 =null= （=true= / =false= / =yes= / =no= / =on= / =off= / =null= / =~= ，按 =downcase= 比较）。加引号时转义 =\\= 与 =\"= 。

- =${VAR}= 含 ={= 、=}= 、=:= ，于是一律带引号， *不插值、不转义 =$=* ；
- =image= 是唯一裸写的字段（镜像引用属已知安全值）；
- =environment= 的值 =redis://cache:6379/0= 因含 =:= 而带引号，=dev= 之类裸写。

** 命名与挂载

- *compose 项目名* ：本次渲染的组 *全部* 为 shared → =ebc-shared= ；否则 =ebc-<project>= 。项目名与所有组名都要过 =[a-z0-9_-]+= 校验，不合法直接 signal。
- *命名卷* ：=:type volume= 渲染为 =ebasecamp-<scope>-<group>-<source>= （scope 取 =shared= / =per-project= ），挂载形如 =ebasecamp-per-project-app-api-cache:/cache= ，并在 *顶层 =volumes:=* 段以空映射声明（去重）。加引号是因为含 =:= 。
- *bind 卷* ：渲染为 ="<source>:<target>"= ，不做路径绝对化（保持清单里的相对形式，相对当前 compose 文件所在目录解析）；=:read-only= 非 nil 时追加 =:ro= 。
- *容器名* ：插件 *不设* =container_name= ，由 compose 按 =<compose 项目名>-<service>-1= 推导，避免跨项目重名。

** 标签与网络

- 每个服务注入五项：=ebasecamp.managed= （固定 ="true"= ）、=.project= 、=.group= 、=.service= 、=.scope= （=shared= / =per-project= ）。用户 =:labels= 先写入，同名键由注入项 *覆盖* （用户无法伪造归属）。
- 服务网络列表 = 原有网络（去重）+ =ebasecamp= （仅当 =:shared-network= 非 nil）。=ebasecamp= 在顶层声明为 external network；其余网络以 =name: {}= 声明，让 compose 按项目创建（不声明会让 =config -q= 报引用未定义网络的错）。
- 状态采集只认这五个标签，标签与容器名不一致时以标签为准。

** depends_on

| 场景 | 行为 |
|------+------|
| 按 scope 渲染（=GROUP-FILTER= 非 nil，写缓存生成物） | 只保留属于本次渲染服务的名字 —— 跨 scope 的依赖在另一个 compose 项目里，保留会让 =docker compose up= 报 depends on undefined service |
| 全量渲染（=GROUP-FILTER= 为 nil，预览 / 导出） | 保留全部依赖，供执行层计算跨 scope 依赖闭包 |

剔除后列表为空则该键整个不输出。执行层（=start=）另用 =:requires-shared= 先把 shared 批次补起来，见 [[file:architecture.org][架构与分层]]。

* 已知限制

以下都是 *当前实现* 的真实边界，不是待修 bug 的托词；逐条都能在 =openspec/tech-debt.md= 找到对应条目。

| 限制 | 后果 | 追踪 |
|------+------+------|
| =env_file= 对象形态的 =required= / =format= 在导入时丢弃（只留 =path= ） | 需要 =required: false= （文件缺失不报错）或 =format: raw= 的 compose，往返后语义回到默认值 | tech-debt #22（未修） |
| =:extra= 原样透传，不做 schema 校验 | 清单里写非法 compose 字段（如 =description= ）会让生成的 =config -q= 失败；错误指向生成物而非清单 | tech-debt #8 |
| 端口只表达「tcp + 绑定全部接口 + 有 published」 | udp、端口区间、特定宿主 IP 的端口只能经 =:extra= 透传，界面里也看不到这些端口 | tech-debt #21 遗留 |
| *同一服务同时有可表达端口与不可表达端口* （或 bind 卷与 tmpfs 卷）时渲染出 *重复的服务键* | =:ports= 与非空的 =:extra= ="ports"= 桶各写一个 =ports:= 行，compose 解析即失败（实测 =mapping key "ports" already defined= ，退出码 1）；只含其中一种时正常 | 未记录，属待开条目 |
| =healthcheck= 只保留五项 | 其他子字段（如 =start_interval= ）往返后丢失 | tech-debt #3 |
| 导出物 *带* =ebasecamp.*= 标签 | 这是 *不变量 2 的正确行为* ：部署机上用 =docker ps --filter label=ebasecamp.managed=true= 仍能识别容器；不是缺陷 | AGENTS.md 不变量 2 |
| 导出物 *不可迁移* | =env_file= 与 bind 卷的相对路径按 *导出文件所在目录* 解析；把 =:export-file= 指到项目根之外，导出物里的 =./db.env= 必然找不到，校验阶段就会被拦（=env file … not found=） | 由 compose 语义决定，无计划 |
| 同一服务名出现在多个组 | 渲染时静默 *保留首个* ，不报冲突 | tech-debt #9 |
| 自定义网络的 =external= 语义无法表达 | 清单只能声明「由本项目创建」的网络 | tech-debt #9 |
