* 4. 问题清单

** 4.1 blocking（1 条，建议降级 major）

*B1 段级键按「焦点」而非「point」解析，与 Readme 措辞不符，且失效时无任何提示*
- 现象：界面内先按 `f` 跳到某个 *组*（焦点留在左树），再在右栏服务行上按 `s`/`x`/`r` → *不派发、无 notice、无 message*。探针必须 `(ebox-focus nil)` 清焦点后才恢复正常。
- 机制：根 Host `:key-scope 'local` 使 `etaf--keys-chain` 在任何焦点存在时*从焦点起算*。`docs/architecture.org`「焦点优先于 point」一节有记载。
- 文档冲突：`Readme.org` 段级键位节写「*point* 落在某个配置段内时额外生效」与「*point* 在左栏或顶栏时按这几个键无反应」—— 两处都是 point 语义。
- 证据：T5a.5 首次运行 `binding-s=nil`、派发 0 次；`(ebox-focus nil)` 后立即 `action=start project=proj-a`。
- 建议：①`Readme.org` 段级键位改为「*焦点*所在配置段生效（无焦点时按 point 兜底）」②`docs/troubleshooting.org` 加一条「按 `s` 没反应：先按 `2` 或点击右栏」③可选：焦点在树内而 point 在段内时给一次 `message` 提示。
- 分级说明：按「就高不就低」记 blocking；若确认主流程（点击右栏 / 按 `2`）不受影响，可降为 major。

** 4.2 major（2 条）

*M1 导入把 compose 归一化注入的 =name:= 持久化到清单*
- 现象：`docker compose config --format json` 会给顶层 `configs`/`secrets` 补 `name: <源目录名>_<键>`（T7 实测 `name: work_review_conf` / `work_db_pass`，`work` 来自源 compose 所在目录名）。导入层忠实写入 `:file-configs` / `:file-secrets`，导出又原样输出。
- 影响：用一个*与环境相关*的名字把 compose 对象名 pin 死；而导出项目名是 `ebc-<project>`，两者不一致，跨项目可能撞名；同时清单不再是「只记录用户意图」的事实源。
- 证据：T7 导出 JSON 交叉复核（python 独立读取）复现。
- 建议：导入时若 `name` 等于 compose 默认派生值（`<project>_<key>`）则丢弃，只保留用户显式声明的 `name`；需在 `ebasecamp-import-parse-json` 加判定 + 往返 ERT。技术债待登记。

*M2 预校验失败路径丢失 =:preflight-warnings=*
- 现象：`ebasecamp-command--preflight-report` 返回的 plist *不含* `:preflight-warnings`，只有成功路径经 `--dispatch` 透传。
- 影响：项目 `:root` 为 nil（相对 `file:` 无法校验）且某分支 `check-compose` 失败时，用户只看到错误、拿不到「相对 `file:` 无法校验」的提示 —— 容易误判成配置写错。
- 证据：T3.D（成功路径 warnings=1 正常透传）vs T3.E（失败路径 report 无该键）。
- 建议：`--preflight-report` 补该键并在失败分支透传；UI 失败提示追加「（N 条预校验警告）」；补 ERT。

** 4.3 minor（8 条）

1. *root=nil 的 warning 文案不足*：只说「无法校验」，没说明「运行时将按生成物所在 cache 目录解析」，用户可能以为只是少校验一次（T3.C）。
2. *=--button-key-hints= 渲染索引零消费*：`ebasecamp-ui--footer-view` 硬编码 `"I"/"o"/"D"`、`--instance-header` 硬编码 `"s"/"x"/"r"`，键名在事实源与渲染层*两处独立维护*；`--button-key-hints` 只被测试引用（code-reviewer 问题 1）。这是技术债 #45 的增强证据。
3. *`?` 帮助面是搜索式 catalog 且需翻页*：21 条根级键要 `C-v` 逐页才对得完，既有 `help-surface-mentions-keys` 只断言首屏 4 条，覆盖偏弱（T5b.9 用翻页验证 21/21 + 5/5 通过）。
4. *`:extra` 吸收 compose 归一化噪音*：导入的 ports 额外项含 `("mode" . "ingress")`（compose 派生字段，非用户输入）被写进清单，与「清单只保存用户意图」有张力（T7）。
5. *`h` 在左树内永不移动焦点*：Readme 写「到边界才落回焦点左移 / 右移」，但左树是最左列，`left` 边界无处可移；`--move-focus` docstring 已写明返回 nil（T5a.2）。
6. *`ebasecamp-status-group-records` 零调用且名字误导*：签名 `(records project group)` 精确双键过滤、*无 scope 语义*；`lisp/` 内零调用，只有定义与测试引用。后续若有人用它渲染 shared 组会静默漏记录（T4.4b）。
7. *Readme 命令表漏列 1 条命令*：实现 `commandp` 为真的非私有 `ebasecamp*` 命令 **17 个**，Readme「命令表」写「共 16 个」且表内 16 条，漏 `ebasecamp-ui-avy-jump`（T9）。
8. *`:root` 为 nil 的三条降级中，「导出须显式选路径」只在交互路径验证过*：非交互路径 `signal` 行为由既有用例覆盖，本次未重复（记录为覆盖边界，非缺陷）。
